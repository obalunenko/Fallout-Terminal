# Fallout Terminal

Приложение для настольных RPG: мастер создаёт терминалы в нативном приложении macOS, а игроки открывают общий Fallout-style интерфейс в браузере. Навигация, взлом, роли игроков и состояние терминала синхронизируются сервером внутри приложения.

Поддерживаемая платформа: **macOS 13+ на Apple Silicon (`arm64`)**. Проект использует Go и Wails v3.

## Возможности

- несколько терминалов в одной автоматически сохраняемой JSON-сессии;
- меню из папок, текстовых записей и команд;
- один активный контроллер и наблюдатели с общим авторитетным экраном;
- переподключение игроков без потери текущего представления;
- пять уровней Fallout-style взлома и специальные скобочные последовательности;
- команды с одобрением мастера и долговечным изменением состояния;
- локальный доступ без внешних сервисов;
- опциональная защищённая публичная ссылка через ngrok.

## Быстрый старт для разработки

Требуются:

- Xcode Command Line Tools;
- Go 1.26.x;
- Node.js 20.19+ и npm.

Из корня репозитория запустите:

```bash
go run ./cmd/build dev
```

Команда устанавливает закреплённые frontend-зависимости, проверяет и генерирует контракты, собирает приложение и открывает окно мастера. Отдельно запускать Vite или сервер игроков не нужно. Локальный адрес игроков обычно имеет вид `http://<IP-мастера>:3690`.

Основные команды:

```bash
make help       # список доступных целей
make dev        # разработка
make build      # сборка
make package    # локальный .app
make test       # тесты
make test-race  # тесты с race detector
make check      # полный набор проверок
```

## Как провести игру

1. Создайте новую session JSON или откройте существующую. После выбора файла изменения сохраняются автоматически и атомарно.
2. Добавьте терминалы и соберите их меню из папок, записей и команд.
3. Выберите или создайте player-config, добавьте персонажей и начните трансляцию.
4. Сделайте нужный терминал активным. Сохранённые позднее правки попадут в текущую трансляцию после нажатия **Обновить у игроков**.
5. Игроки открывают показанный приложением адрес и выбирают персонажей. Первый назначенный игрок становится контроллером, остальные — наблюдателями.
6. По окончании сцены завершите трансляцию. Назначения и runtime-состояние очистятся, а долговечные изменения мира останутся в session JSON.

Все общие действия принимает сервер. Наблюдатели видят тот же экран, но не могут управлять терминалом.

## Команды, изменяющие состояние

Для команды можно включить **Изменяет состояние** и настроить четыре обязательных значения:

- исходное название пункта меню;
- название после выполнения;
- текст запроса мастеру;
- текст успешного выполнения.

Пример: **Открыть двери** → **Двери открыты**.

Когда контроллер впервые выбирает такую команду:

1. Все игроки видят **Выполняется запрос**; навигация и другие общие действия блокируются.
2. У мастера открывается диалог с настроенным текстом.
3. **Одобрить** сохраняет изменение и только после успешной записи показывает игрокам результат.
4. **Отклонить** или закрытие диалога ничего не меняет; игроки видят **Запрос отклонён** и могут вернуться в меню.

После одобрения новое название и результат одновременно появляются у контроллера и наблюдателей. Повторный выбор показывает сохранённый результат без нового запроса, выполнения или записи.

Выполненное состояние:

- сохраняется при навигации, переключении терминалов, завершении трансляции, перезапуске приложения и повторном открытии файла;
- привязано к стабильным ID терминала и команды, поэтому переименование и перемещение его не сбрасывают;
- удаляется вместе с командой и не переносится на новую команду;
- фиксирует название и результат на момент выполнения — последующее редактирование применится только после сброса и нового выполнения.

Мастер может подтвердить **Сбросить состояние** для одной команды или **Сбросить все состояния** для выбранного терминала. Команды однонаправленные: автоматического перехода «Открыть» ↔ «Закрыть» нет.

Обычные команды работают как прежде: выполняются сразу, не требуют решения мастера и не меняют название. Старые session JSON `version: 1` открываются без конвертации; отсутствие новых необязательных полей означает исходное состояние. [Demo-сессия](sessions/demo.json) содержит готовые state-changing команды и [список игроков](sessions/demo-players.json).

## Взлом терминала

Уровни 1–5 используют слова длиной от 4 до 8 символов и дают четыре попытки. После догадки терминал показывает число совпавших позиций. Специальные последовательности `()`, `[]`, `{}` и `<>` удаляют неверный вариант или восстанавливают попытки.

Секретное слово и внутренние кандидаты остаются на сервере. Доска, попытки и результат синхронизируются между игроками и восстанавливаются при переподключении.

При переключении терминала во время незавершённого взлома мастер выбирает: сохранить головоломку, сбросить её или остаться в текущем терминале.

## Локальный и публичный доступ

Локальный сервер на порту `3690` запускается вместе с приложением и работает без интернета.

Для внешней ссылки откройте в приложении раздел **Публичный доступ**:

1. укажите личный ngrok authtoken;
2. задайте имя и пароль для игроков;
3. при необходимости укажите зарезервированный домен;
4. сохраните настройки и нажмите **Включить**.

Публичный endpoint защищает статические файлы и RPC одной парой Basic Auth. Authtoken и пароль хранятся только в macOS Keychain и не попадают в session JSON, player-config или публичное состояние. Ошибка ngrok не мешает локальной игре.

## Сессии и данные

- Session JSON сохраняется по явно выбранному пути; новые файлы по умолчанию предлагаются в `~/Documents/Fallout Terminal/Sessions/`.
- Формат остаётся обратно совместимым `version: 1`, включая необязательные настройки и состояния команд.
- Player-config также использует `version: 1` и хранит только стабильные ID и имена персонажей.
- Ожидающие запросы, подключения игроков, роли, активная трансляция и текущий взлом не записываются в session JSON.
- Одобренные состояния команд являются долговечным состоянием мира и сохраняются до явного сброса.
- Встроенный demo-файл доступен только для чтения; для редактирования создайте пользовательскую копию.

Перед экспериментами делайте копии важных сессий.

## Сборка приложения

Локальный ad-hoc подписанный пакет для Apple Silicon:

```bash
go run ./cmd/build package
```

Результат: `build/bin/Fallout Terminal.app`. При первом запуске macOS может потребовать разрешение в **System Settings → Privacy & Security**.

Публичный релиз требует Developer ID signing, notarization и проверки Gatekeeper. Процедура находится в [scripts/build-macos.sh](scripts/build-macos.sh) и [Wails v3 quickstart](specs/006-wails-v3-migration/quickstart.md).

Активная процедура отката: [Wails v3 → v2](docs/wails-v3-migration-rollback.md). Каталоги [спецификации Wails v2](specs/001-wails-v2-migration/) и [старого rollback](docs/wails-migration-rollback.md) — неизменяемые исторические evidence, а не действующие инструкции.

## Структура проекта

- `frontend/` — интерфейс мастера;
- `client/` — браузерный интерфейс игроков;
- `internal/` — домен, хранение, live-state и сервер игроков;
- `proto/` — protobuf-контракты;
- `sessions/` — встроенные примеры session JSON;
- `tests/browser/` — браузерные сценарии;
- `specs/` — спецификации реализованных возможностей.
