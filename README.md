# Fallout Terminal

Приложение для ведущего настольной RPG: мастер создаёт и редактирует терминалы в нативном окне macOS, а игроки видят общий Fallout-style терминал в браузере. Навигация, взлом, подключение новых игроков и восстановление соединения синхронизируются встроенным HTTP/ConnectRPC-сервером.

Приложение работает на Go + Wails v2. Текущий поддерживаемый профиль — **персональное использование на macOS 13+ / Apple Silicon (`arm64`)**. Локально собранный и подписанный ad-hoc пакет `Fallout Terminal.app` принят для этого профиля. Сервер игроков является частью приложения: его не нужно и нельзя запускать отдельной командой.

Публичное распространение — отдельный условный профиль. Он запрещён, пока оператор не выполнит Developer ID signing, notarization, stapling, сборку DMG и проверку Gatekeeper. Отсутствие этих credentials не блокирует персональное использование.

## Возможности

- нативный редактор ведущего и отдельный браузерный интерфейс игроков;
- несколько терминалов в одной JSON-сессии с автоматическим атомарным сохранением;
- древовидный контент из папок, команд и текстовых записей;
- публикация выбранного терминала и явное обновление уже идущей трансляции;
- единая серверная навигация для всех игроков, включая восстановление актуального экрана после переподключения;
- пять уровней взлома, обычные попытки подбора пароля и Fallout-style специальные скобочные последовательности;
- локальная игра без внешних сервисов и опциональный защищённый Basic Auth публичный доступ через ngrok.

## Требования для разработки

- macOS 13 или новее на Apple Silicon;
- Xcode Command Line Tools;
- Go 1.26.x;
- Node.js 20.19+ и npm;
- Wails CLI строго версии 2.13.0;
- бинарник ngrok — только если нужен публичный доступ.

Установка и проверка Wails относятся к подготовке рабочего места, а не к ежедневному запуску:

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@v2.13.0
wails doctor
```

Frontend-зависимости отдельно устанавливать не требуется: корневой `wails.json` поручает Wails выполнить `npm ci`, запустить Vite, собрать Go-приложение и поднять сервер игроков.

## Запуск всей системы одной командой

После установки требований перейдите в корень репозитория и выполните ровно одну команду:

```bash
wails dev
```

Это единственная команда запуска разработки. Не запускайте отдельно `npm run dev`, `go run`, старый Node-сервер или второй терминал. Wails откроет окно мастера и внутри того же процесса поднимет адрес игроков на порту `3690`, обычно `http://<IP-мастера>:3690`.

Если порт занят, приложение должно показать понятную ошибку и не сообщать о готовности. После нормального выхода окно, HTTP/Connect listener и принадлежащие приложению дочерние процессы должны завершиться.

## Рабочий процесс ведущего

1. Откройте существующую сессию формата version 1 или создайте новую. После выбора файла дальнейшие изменения сохраняются автоматически.
2. Создайте один или несколько терминалов. Для каждого можно задать вступительный текст и уровень взлома от 0 до 5.
3. Соберите содержимое терминала из трёх типов узлов:

   - **папка** — вложенное меню, которое может содержать другие узлы;
   - **команда** — пункт, выполняющийся с выводом текста;
   - **запись** — отдельный текстовый экран с названием и описанием.

4. В блоке **Конфигурация игроков** выберите существующий player-config JSON или создайте новый. Пока файл не выбран, редактирование терминалов остаётся доступным, а изменение списка персонажей и запуск трансляции заблокированы.
5. Добавьте персонажей в панели **Игроки и трансляция**, затем начните трансляцию. Каждое изменение списка сначала атомарно сохраняется в player-config. Подключённые браузеры увидят свободных персонажей и смогут выбрать одного; один персонаж не может одновременно принадлежать двум логическим сессиям.
6. При необходимости исправьте состояние со стороны ведущего: переименуйте персонажа или техническую метку сессии, назначьте или освободите персонажа, перенесите его между сессиями и явно выберите активного контроллера. Активный контроллер всегда один; остальные назначенные игроки остаются наблюдателями.
7. Нажмите **Сделать активным**, чтобы показать выбранный терминал всем назначенным игрокам. Последующие правки сохраняются в файл, но попадают в текущую трансляцию только после нажатия **Обновить у игроков**. Кнопка удаления активного терминала с экранов игроков оставляет саму трансляцию, назначения и роли активными: игроки переходят в состояние ожидания терминала.
8. Следите за состоянием взлома и логическими сессиями, а не только за сырым числом браузерных подключений. Несколько вкладок одного профиля относятся к одной сессии; отключившийся контроллер остаётся явно назначенным, пока не переподключится, не будет освобождён или ведущий не передаст управление.
9. Завершите трансляцию отдельным действием, когда нужно закончить сцену. Это очищает текущие назначения и управление; следующая трансляция всегда начинается с нового выбора персонажей.

Игроки открывают показанный в шапке адрес. Все их переходы по меню и действия во время взлома применяются сервером к одному общему состоянию, поэтому группа видит один и тот же экран.

### Персонажи, роли и исправление назначений

Имя выбранного персонажа является основной идентичностью в браузере игрока. Автоматическая метка вида `PLAYER N` остаётся отдельной технической подписью устройства; изменение такой метки не переименовывает персонажа. И персонажи, и распознанные сессии имеют стабильные runtime-идентификаторы, поэтому одинаковые отображаемые имена не объединяют записи.

Игрок без назначения видит список персонажей текущей трансляции. Первый успешно завершивший выбор при отсутствии контроллера становится активным контроллером; последующие назначения становятся наблюдателями. Наблюдатель получает тот же авторитетный экран и сохраняет локальные hover, focus, просмотр страниц и ввод-превью, но не может отправлять общую навигацию или действия взлома. Передача управления применяется сразу во всех вкладках: прежний контроллер становится read-only, новый получает право отправки без сброса терминала или головоломки.

Панель ведущего предназначена и для исправления ошибок за столом. Освобождение персонажа возвращает соответствующую сессию к выбору. Назначение или перенос выполняются по стабильным идентификаторам и не дают браузеру оптимистически менять роль или общее состояние: интерфейс игрока обновляется только после авторитетного ответа сервера.

### Переключение терминалов и незавершённый взлом

Если в текущем терминале нет незавершённой головоломки, другой терминал активируется сразу. Если взлом ещё идёт, переключение приостанавливается и ведущий должен выбрать одно из трёх действий:

- **Сохранить и переключить** — точное приватное состояние головоломки приостанавливается. При возврате восстанавливаются та же доска, попытки, удалённые варианты, использованные последовательности, журнал и результат; пока терминал неактивен, действия игроков для него отклоняются.
- **Сбросить и переключить** — текущая runtime-головоломка удаляется. При следующем запуске взлома этого терминала создаётся новая головоломка по обычным правилам.
- **Остаться в терминале** — переключение отменяется, а текущий терминал и головоломка остаются без изменений.

Пока диалог решения открыт, исходный терминал остаётся единственным авторитетным активным терминалом. Устаревшее решение после другой lifecycle-операции отклоняется и показывается как ошибка, а не применяется к новому состоянию.

### Распознавание браузера и границы времени жизни

При первом подключении сервер выдаёт браузеру непрозрачный token распознавания. В `localStorage` хранится только этот token: имя, персонаж, роль, список персонажей, терминал и головоломка в браузере не сохраняются. Область распознавания — точное сочетание origin и профиля браузера:

- перезагрузка, повторное открытие и другие вкладки того же origin в одном профиле используют одну логическую сессию;
- другой профиль, приватное окно, другой origin или очищенное хранилище создают отдельную логическую сессию;
- token распознавания не является аутентификацией и никогда сам по себе не даёт право управлять терминалом;
- после перезапуска приложения прежний token неизвестен новому процессу: сервер выдаёт замену и создаёт новую сессию без прежнего имени, персонажа или роли.

Границы трансляции, процесса и player-config различаются. Завершение трансляции очищает занятость персонажей, контроллера, активный и приостановленные runtime-терминалы, незавершённые решения и кэш запросов. В том же процессе сохраняются распознанные логические сессии, их технические метки и загруженный авторский список персонажей; поэтому при начале следующей трансляции каждый игрок выбирает персонажа заново. Полный выход и новый запуск приложения очищают сессии, метки, claims, управление и runtime-терминалы, но при повторном открытии сессии её player-config автоматически восстанавливает только стабильные ID и имена персонажей.

Эти runtime-данные не входят ни в JSON-сессию version 1, ни в player-config. Сессия может содержать только необязательную относительную ссылку `playerConfig`; сам отдельный файл хранит `version`, `name` и упорядоченный массив `roster` из стабильных `id`/`name`. Настроенные терминалы и существующее долговечное состояние разблокировки не удаляются ни завершением трансляции, ни сбросом runtime-назначений.

### Приватная команда успешного взлома

**Взлом успешен** (`ForceHackSuccess`) остаётся точной доверенной операцией только интерфейса ведущего. Она может завершить текущую активную незавершённую головоломку, включая исходную головоломку во время ожидающего решения о переключении, и публикует получившееся общее состояние в обычном серверном порядке.

У этой операции нет публичной ConnectRPC-процедуры, HTTP endpoint, query-параметра, DOM-кнопки, глобальной функции или клавиатурного пути в браузере игрока. Наличие token, назначение персонажа или роль активного контроллера не открывают это полномочие.

## Механика взлома

Уровни 1–5 используют слова длиной от 4 до 8 символов и дают четыре попытки. После обычной догадки терминал показывает количество совпавших позиций, как в Fallout. Секретное слово и служебная таблица кандидатов никогда не отправляются в браузер.

Каждая новая головоломка содержит от 3 до 6 специальных последовательностей `()`, `[]`, `{}` или `<>`. Последовательность находится в одной строке и не содержит букв между парными скобками. Игрок выбирает её по открывающей скобке; использовать каждую пару можно только один раз:

- с вероятностью 80% удаляется один неправильный вариант пароля;
- с вероятностью 20% восстанавливаются все попытки;
- если неправильных вариантов больше нет, вместо удаления восстанавливаются попытки.

Состояние использованных последовательностей, удалённых вариантов и оставшихся попыток синхронизируется между игроками и сохраняется при переподключении. Игровых команд для принудительного успеха или массового удаления вариантов у игроков нет; такое полномочие остаётся только у ведущего.

## Локальный и публичный режим

По умолчанию `wails dev` работает только в локальной сети и не запускает ngrok.

Для публичного режима сначала установите ngrok, настройте токен аккаунта и зарезервируйте используемый HTTPS-домен. Это одноразовая подготовка:

```bash
ngrok config add-authtoken <ВАШ_ТОКЕН>
```

Затем запустите всю систему одной командой из корня репозитория:

```bash
NGROK_ENABLED=1 NGROK_USERNAME=players NGROK_PASSWORD='<ПАРОЛЬ_ОТ_8_ДО_128_СИМВОЛОВ>' wails dev
```

Вместо пары переменных можно передать combined credential, сохранив тот же единственный вызов:

```bash
NGROK_ENABLED=1 NGROK_BASIC_AUTH='players:<ПАРОЛЬ_ОТ_8_ДО_128_СИМВОЛОВ>' wails dev
```

Дополнительные параметры:

- `NGROK_DOMAIN` — домен; по умолчанию `fallout-terminal.ngrok.app`;
- `NGROK_BIN` — полный путь к бинарнику, если `ngrok` отсутствует в `PATH`;
- `NGROK_TIMEOUT` — положительная Go-длительность, например `30s`;
- `NGROK_TIMEOUT_MS` — положительный тайм-аут в миллисекундах.

Публичный режим fail-closed: без корректного логина и пароля процесс ngrok не запускается, а локальный адрес продолжает работать. Статические ресурсы и ConnectRPC защищаются одной Basic Auth policy. Кредентиалы не записываются в сессии или интерфейс; временный policy-файл имеет приватные права и удаляется после запуска или обработанной ошибки.

### Контракт ConnectRPC и генерация

Единственный поддерживаемый публичный протокол игроков — сгенерированный `fallout.terminal.player.v1.PlayerService`: server-streaming `Subscribe` и отдельные unary-процедуры `SelectCharacter`, `Navigate`, `Guess`, `ActivatePattern`, `SoundManifest`. Браузер вызывает их на том же origin; старого WebSocket/JSON player protocol и совместимого маршрута больше нет.

Схемы находятся в `proto/fallout/terminal/`. Go-код генерируется только в `internal/gen`, а публичный ECMAScript — только в `client/gen`. `wails dev` и `wails build` перед запуском Vite автоматически синхронизируют `proto/schema-revision.txt` и полностью регенерируют оба дерева. Для отдельной ручной генерации после изменения `.proto` выполните:

```bash
npm ci --prefix client
scripts/proto-generate.sh --sync-revision
scripts/proto-check.sh
scripts/proto-breaking.sh --all-fixtures
```

Без `--sync-revision` генератор работает строго и сообщает несовпадение revision; этот режим используется проверками, чтобы изменение схемы и производных файлов попадало в одно ревьюируемое поколение. Ошибка `buf breaking` требует совместимого изменения или осознанной новой версии пакета; не перезаписывайте baseline, чтобы скрыть удаление поля/enum/RPC. Ошибка browser graph означает, что публичная схема или bundle импортирует приватный, persistence либо config контракт.

Для проверки уже собранного приложения с теми же переменными можно выполнить его бинарник одним вызовом:

```bash
NGROK_ENABLED=1 NGROK_USERNAME=players NGROK_PASSWORD='<ПАРОЛЬ>' './build/bin/Fallout Terminal.app/Contents/MacOS/Fallout Terminal'
```

Обычный локальный пользователь запускает установленный `Fallout Terminal.app` одним открытием в Finder; Go, Node, npm, Vite и Wails CLI для этого не нужны.

## Сессии и данные macOS

- Новый файл по умолчанию предлагается в `~/Documents/Fallout Terminal/Sessions/`. Каталог создаётся только после подтверждения диалога сохранения.
- Пользователь выбирает фактический путь файла; последующие атомарные сохранения продолжают писать туда же.
- Player-config выбирается или создаётся отдельным native-диалогом. Сессия сохраняет нормализованную относительную ссылку, поэтому совместно перемещённое дерево каталогов остаётся переносимым; один player-config можно использовать из нескольких сессий.
- Созданный player-config имеет `version: 1`, имя из имени файла и пустой `roster`. Файл содержит только стабильные ID и имена персонажей; browser tokens, логические сессии, присутствие, claims, controller, broadcast, терминалы и головоломки туда не записываются.
- Отмена диалога, отсутствующая ссылка или невалидный файл не закрывают сессию и не создают частичный список: выберите другой файл или создайте новый. Ошибка записи списка оставляет и файл, и авторитетное runtime-состояние без изменений.
- Встроенный `sessions/demo.json` внутри ресурсов приложения доступен только для чтения. Для редактирования мастер явно создаёт пользовательскую копию.
- Метаданные приложения, если они понадобятся, размещаются в `~/Library/Application Support/com.vaulttec.fallout-terminal/`. Содержимое сессий туда не переносится.
- Приложение не должно записывать пользовательские данные внутрь `.app` или рядом с ним.

Перед экспериментами используйте копии важных `.json`-сессий. Формат совместимости остаётся версией 1; runtime-состояние трансляции, взлома, игроков и туннеля в файл не сохраняется.

## Проверки

Основные автоматические проверки из корня репозитория:

```bash
gofmt -l .
go vet ./...
go test ./...
go test -race ./...
npm ci --prefix frontend
npm run build --prefix frontend
npm ci --prefix client
npm run build --prefix client
npm ci --prefix tests/browser
npm test --prefix tests/browser
scripts/proto-check.sh
scripts/proto-breaking.sh --all-fixtures
```

`gofmt -l .` не должен печатать имена Go-файлов. Race-проверка обязательна для live/player кода. Полный ручной сценарий с 4–7 браузерами, reconnect, звуком, публичным доступом и упаковкой находится в [quickstart миграции](specs/005-connectrpc-protobuf-migration/quickstart.md).

## Активная персональная сборка macOS

Собрать тестовый Apple Silicon `.app` без релизных credentials:

```bash
wails build -clean -platform darwin/arm64
```

Ожидаемый результат — `build/bin/Fallout Terminal.app`. Это активный персональный пакет: он должен запускаться без dev-серверов и инструментов, открывать локальный адрес игроков, содержать все master/player assets и корректно завершать listener. Wails создаёт локальную ad-hoc подпись; при первом запуске перенесённого пакета macOS может потребовать одноразовое разрешение через **System Settings → Privacy & Security → Open Anyway**. Не отключайте Gatekeeper глобально и не публикуйте этот пакет как Developer ID release.

## Условный публичный релиз и notarization

Релизный DMG допустим только после полного конвейера: Developer ID Application signing с hardened runtime, проверка `codesign`, отправка через `xcrun notarytool` с Keychain profile, успешная notarization, stapling и проверка Gatekeeper через `spctl`.

Репозиторный entry point для этого конвейера — `scripts/build-macos.sh`. Сначала укажите не секреты, а ссылки на установленную signing identity и заранее созданный Keychain profile, затем выполните preflight:

```bash
export DEVELOPER_ID_APPLICATION='Developer ID Application: Organization Name (TEAMID)'
export NOTARYTOOL_KEYCHAIN_PROFILE='fallout-terminal-notary'
scripts/build-macos.sh --preflight
```

Preflight проверяет macOS/arm64, Go, Wails CLI, entitlements, signing identity и доступ к notary service. Он не собирает приложение и ничего не отправляет на notarization. После успешной проверки запустите полный конвейер:

```bash
scripts/build-macos.sh
```

Скрипт собирает и подписывает `.app`, проверяет архитектуру и hardened runtime, нотариализует и staples приложение, создаёт подписанный `build/bin/Fallout-Terminal-arm64.dmg`, затем нотариализует, staples и проверяет DMG через Gatekeeper. В конце выводятся пути и SHA-256 артефактов; значения credentials в вывод не попадают.

На данный момент README **не утверждает**, что подписанный/notarized/stapled DMG уже получен или прошёл Gatekeeper. Такое утверждение допустимо только после записи реального evidence в [quickstart миграции](specs/001-wails-v2-migration/quickstart.md). Официальные справки: [Apple — notarizing macOS software](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) и [Apple — distribution and releases](https://developer.apple.com/documentation/xcode/distributing-your-app-for-beta-testing-and-releases).

## Восстановление после ошибки

- **Порт 3690 занят:** корректно закройте предыдущий экземпляр Fallout Terminal или другой известный процесс, затем снова выполните единственную команду запуска. Не поднимайте сервер игроков вручную на другом порту.
- **Публичный режим не запускается:** локальная игра остаётся доступна. Проверьте `NGROK_USERNAME`, длину пароля, `NGROK_BIN`, зарезервированный HTTPS-домен и токен ngrok; либо уберите `NGROK_ENABLED` и перезапустите локально.
- **Прерван `wails dev` с активным ngrok:** предпочтительно сначала закрыть нативное приложение через Quit. Если supervisor был аварийно остановлен, найдите только тестовый процесс командой `pgrep -fl '[n]grok'` и завершите конкретный PID через `kill -TERM <PID>`; не используйте широкое удаление процессов.
- **Сессия не открывается:** исходный файл не заменяется при ошибке валидации. Сохраните его копию и проверьте, что это корректный JSON формата version 1.
- **Новая Wails-сборка не прошла персональный acceptance:** переключитесь на зафиксированный Electron rollback commit или артефакт по [процедуре отката](docs/wails-migration-rollback.md). Публичные trust gates не влияют на решение о персональном откате.

## Отложенные платформы

Первый поддерживаемый релиз — только macOS 13+ / Apple Silicon. Intel Mac, universal macOS binary и Windows/WebView2 отложены и не должны считаться проверенными или распространяться как поддерживаемые сборки. Текущий путь разработки Wails всегда начинается с `wails dev`; Electron-исходники доступны только через зафиксированную rollback-ревизию.
