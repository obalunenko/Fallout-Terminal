# Bug Report: Delimiter Symbols Cannot Be Selected Independently

**Type**: Spec conflict
**Severity**: Medium
**Feature**: `feature/003-hacking-game-evolution` — Phase 1 Server-Authoritative Hacking Patterns
**Reported**: 2026-08-11
**Status**: Patched
**Patched**: 2026-08-11

## Description

Special delimiter symbols such as `(`, `)`, `[`, `]`, `{`, `}`, `<`, and `>` must remain individually selectable when the selected symbol is not the opening character of a currently valid special-pattern combination. This includes standalone delimiters that do not form a valid combination and non-opening characters inside a valid combination.

The whole inclusive special-pattern span must highlight and activate only when the player targets the pattern's first (opening) symbol. Hovering, focusing, or selecting an interior or closing symbol must not resolve to the whole pattern; it must retain the ordinary single-symbol interaction.

The current artifacts and implementation require the opposite behavior in two places:

- standalone and otherwise invalid delimiter symbols are inert and cannot be selected; and
- every offset from a valid pattern's opening through closing symbol resolves to, highlights, and activates that whole pattern.

- **Affected requirements**:
  - **FR-004** preserves ordinary behavior only for “non-delimiter filler clicks” and must be expanded or complemented with explicit delimiter-symbol behavior.
  - **FR-012** defines the pattern as an inclusive opening-through-closing coordinate range but does not distinguish the single opening-cell activation target from the highlighted/effected span.
  - **FR-063**, **FR-072**, and **FR-073** define standalone delimiter decoys as a separate board category; their interaction semantics must no longer imply inertness.
  - **FR-075** explicitly requires a standalone delimiter decoy not to highlight, produce a request, consume an attempt, or change state. This conflicts directly with individual selection.
  - **FR-077** permits validity to be revealed through normal interaction but does not constrain full-span interaction to the opening symbol.
  - **FR-081** and **FR-082** correctly keep invalid delimiters out of the public pattern projection, but the spec currently treats absence from that projection as absence of all selectable behavior.
  - **SC-013** covers non-delimiter filler clicks only and lacks delimiter-symbol selection coverage.
  - **SC-015** explicitly requires delimiter decoys to be no-ops and valid patterns to retain inclusive interaction behavior, directly conflicting with the reported expectation.
- **Gap/conflict identified**: The spec conflates a pattern's inclusive effect/highlight range with its activation hit area, and it conflates “not a valid pattern” with “not individually selectable.” It needs separate rules for (1) ordinary single-symbol selection and (2) opening-symbol-only pattern activation.

## Root Cause Analysis

This behavior was intentionally encoded by the current specification rather than introduced by implementation drift. The camouflage requirements defined invalid delimiter symbols as inert, and convergence task T048 deliberately expanded valid-pattern hit resolution across every inclusive offset. The browser and domain then implemented those rules, and the regression suites locked them in. The newly reported expectation changes the interaction contract: delimiter validity should determine whether the opening symbol activates a pattern, not whether the glyph can be selected at all.
