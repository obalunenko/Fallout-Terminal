# Bug Report: Неполноэкранный результат команды и неверная навигация ожидания

**Type**: Spec gap
**Severity**: High
**Feature**: `009-state-changing-menu-commands`
**Reported**: 2026-08-18
**Status**: Patched
**Patched**: 2026-08-18

## Description

После выбора игроком изменяющей состояние команды весь lifecycle запроса должен отображаться как отдельный полноэкранный экран результата, аналогичный полноэкранному просмотру записи, а не как результат внутри списка меню.

Ожидаемое поведение:

1. Сразу после выбора команды всем игрокам показывается полноэкранный экран ожидания решения мастера.
2. Пока мастер не одобрил и не отклонил запрос, `Back`, `Enter` и остальные действия навигации не должны возвращать игроков в меню или менять общую позицию терминала.
3. После отклонения всем игрокам на том же полноэкранном экране показывается «Ошибка доступа». Только после `Back` или `Enter` контроллера все представления возвращаются в прежнее меню; команда остаётся в исходном состоянии.
4. После одобрения и успешного сохранения всем игрокам на том же полноэкранном экране показывается настроенный текст успешного выполнения. Только после `Back` или `Enter` контроллера все представления возвращаются в прежнее меню.

Текущее поведение и артефакты покрывают отдельный экран `pending/rejected` и возврат из отклонения только через `Back`, но успешный результат рендерится как панель над списком меню. `Enter` не определён как подтверждение ни отклонённого, ни успешного результата, а отклонение называется «Запрос отклонён», а не «Ошибка доступа».

## Root Cause Analysis

Первопричина — пробел presentation contract. Исходная спецификация зафиксировала бизнес-состояния и их тексты, но не зафиксировала форму экрана и полную таблицу допустимых клавиш на каждом переходе. План и T025 поэтому реализовали специальный полноэкранный статус только для `pending/rejected`, разрешили выход из rejection только через `Back`, а успешный результат оставили в прежней command-output панели внутри списка.

Автоматические проверки воспроизводят именно это неполное описание: pending проверяется как заблокированный, rejection — как экран с `Back`, approve — как наличие текста с последующим кликом `Back`. Они не проверяют отсутствие меню на success screen, `Enter` как acknowledgement и новое сообщение «Ошибка доступа», поэтому дефект прошёл T040.
