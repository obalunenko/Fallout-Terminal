# Bug Report: Состояния команды рендерятся не как описание записи

**Type**: Implementation drift
**Severity**: Medium
**Feature**: `009-state-changing-menu-commands`
**Reported**: 2026-08-18
**Status**: Patched
**Patched**: 2026-08-18

## Description

После выбора изменяющей состояние команды служебный текст ожидания решения мастера и текст результата после изменения состояния должны отображаться тем же способом, что и описание обычной записи, выбранной в меню. Рендер описания записи является эталоном для presentation командного lifecycle: та же область записи, типографика, переносы, последовательное раскрытие текста, пагинация и поведение при изменении размеров экрана.

Ожидаемое поведение:

1. В `PENDING` текст «Выполняется запрос» отображается через тот же presentation/rendering path, что и описание выбранной записи, при сохранении запрета `Back`, `Enter` и остальных shared actions.
2. После успешного перехода в `COMPLETED` frozen result отображается как описание записи, включая одинаковые reveal/pagination/layout semantics, и остаётся до общего acknowledgement контроллера.
3. `REJECTED` («Ошибка доступа») использует тот же единый экран записи, поскольку входит в уже определённый lifecycle `PENDING → REJECTED|COMPLETED`.
4. Controller и observers видят одинаковый record-style экран; observers не получают локального способа завершить его.

Текущая реализация использует разные поверхности. Обычная запись открывает `#termEntry`, выводит описание в `#entryBody` и запускает общий `activatePagination(...)/revealInto(...)`. `PENDING`/`REJECTED` скрывают `#termEntry`, деактивируют pagination, записывают строку напрямую в отдельный `#termOutput` и центрируют её стилем `.command-execution-status`. `COMPLETED` включает pagination/reveal, но остаётся на отдельной `.term-output.command-screen` поверхности с собственной рамкой, фоном, отступами и геометрией вместо эталонного `.term-entry/.entry-body` представления.

## Root Cause Analysis

BUG-004 уточнил артефакты до «единого полноэкранного представления записи», но реализация интерпретировала это преимущественно как «скрыть список меню и растянуть отдельный command output». В `client/client.js` ветка обычной записи использует `#termEntry/#entryBody` и `activatePagination`, ветка `PENDING/REJECTED` отключает pagination и напрямую задаёт `#termOutput.textContent`, а ветка `COMPLETED` добавляет pagination поверх того же отдельного `#termOutput`. В `client/client.css` эта поверхность сохраняет стили command-output pane и для status дополнительно центрирует текст, поэтому она не эквивалентна рендеру описания записи.

Проверки BUG-004 закрепили неполную интерпретацию: helper `expectFullScreenCommandSurface` проверяет `#termOutput`, класс `command-screen`, нужный текст и отсутствие меню, а `#termEntry` ожидает скрытым. В результате T062–T064 и T040 могли пройти, не проверяя сформулированный в FR-006/FR-008/FR-033 record-renderer contract.
