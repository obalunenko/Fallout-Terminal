# Bug Report: Undersized Hacking Password Screen

**Type**: Spec gap
**Severity**: Medium
**Feature**: 002-responsive-desktop-layout (Responsive Desktop Player Layout)
**Reported**: 2026-08-10
**Status**: Patched
**Patched**: 2026-08-10

## Description

The hacking password screen renders noticeably smaller than the other player-terminal states. Its board, attempts, activity log, and input preview must use the available viewport more effectively and remain comfortably readable while fitting together on one screen.

The hacking game is a single-screen interaction: its content must be adjusted and reflowed to fit the supported viewport without browser-page scrolling, localized scrolling, or terminal-native pagination. Pagination remains appropriate for oversized information text, but it must not be used as a fallback for the hacking board.

## Artifact Traceability

### spec.md

- **Affected user stories**:
  - **User Story 1 — See the complete terminal at once**: Acceptance Scenario 1 requires the complete hacking interface to remain visible without scrolling, but it does not require the hacking content to retain a readable visual scale comparable to the other states.
  - **User Story 2 — Use the terminal across desktop screen sizes**: Acceptance Scenarios 1 and 2 require coherent scaling and a visible, usable hacking board, but they do not define a hacking-specific readability floor or state that the board must remain a single, non-paginated screen.
- **Affected requirements**:
  - **FR-003** requires the header, active content, and controls to remain simultaneously visible; the hacking layout must satisfy this by adjusting its internal geometry rather than making the whole game disproportionately small.
  - **FR-004** prohibits clipping and overlap but does not prevent excessive shrinking.
  - **FR-005** requires the hacking board data, attempts, activity log, input preview, and interactions to remain visible and usable at every supported desktop viewport, but “usable” is not backed by a measurable hacking-text size or density criterion.
  - **FR-006** permits a fixed hierarchy among font roles but does not constrain the hacking role relative to normal terminal text. The current artifact therefore allows the hacking role to be materially smaller while still satisfying the shared-scale rule.
  - **FR-007** requires the frame to preserve the usable content region, but it does not specify that hacking content should expand to use that region when space is available.
  - **FR-008** allows oversized content to be fitted or paginated globally; it does not explicitly exclude the interactive hacking board from pagination or require a one-screen fit strategy for that state.
- **Affected success criteria**:
  - **SC-002** checks visibility, overlap, and clipping but does not measure whether the hacking presentation is too small relative to other states.
  - **SC-007** verifies shared scale-factor ratios, which can pass even when the chosen hacking multiplier is uncomfortably small.
  - **SC-001** and **SC-008** verify zero scrolling and information-view pagination, but neither establishes that hacking must fit as one readable, non-paginated interaction.
- **Gap identified**: The specification requires the hacking screen to fit but does not define an acceptable hacking-text scale, require it to use the available screen area, or explicitly reserve pagination for non-interactive information content. This permits an implementation to satisfy the mechanical fit and shared-scale checks by rendering the password game disproportionately small.

### plan.md

- **Affected sections**:
  - **BUG-001 Implementation Notes — shared responsive scale and fixed role multipliers**.
  - **BUG-001 Implementation Notes — fit bounded terminal states and paginate overflowing information text**.
  - **BUG-001 Complexity Notes — rendered metrics, viewport height, and persistent-region sizing**.
- **Impact**: The plan must add a hacking-specific single-screen fitting strategy. It should define how board columns, row and column gaps, log allocation, padding, and responsive orientation adapt before reducing hacking text, set a readable hacking scale relative to normal terminal text, and explicitly prevent the information-view paginator from being used for the hacking game.

- **Missing tasks**:
  1. Define the minimum acceptable hacking text scale and its relationship to normal terminal text across the supported desktop viewport matrix.
  2. Rebalance hacking-board columns, gaps, padding, activity-log width/height, and compact orientation so all game content fills and fits the viewport without scrolling or pagination.
  3. Add regression coverage proving that hacking remains a single screen, never activates page controls, has zero scrollable regions, and meets the new readability and screen-use criteria.
  4. Repeat visual browser verification for the densest supported hacking fixture at every required viewport and at 200% zoom, comparing its scale with the otherwise acceptable terminal states.

## Root Cause Analysis

The responsive feature specified mechanical containment more precisely than visual readability for the hacking state. The shared scale design fixed the hacking font at a smaller role multiplier, while the completed tests mainly assert CSS structure, proportional scaling, lack of overflow, and content visibility. Those checks can all pass when the game technically fits but looks noticeably undersized. The artifacts also do not explicitly distinguish the interactive hacking board, which must remain one complete screen, from long information content that may use CRT-style pagination.
