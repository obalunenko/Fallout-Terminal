# Bug Report: Inconsistent Type Scaling and Scroll-Based Information Views

**Type**: Spec conflict
**Severity**: High
**Feature**: 002-responsive-desktop-layout (Responsive Desktop Player Layout)
**Reported**: 2026-08-09
**Status**: Patched
**Patched**: 2026-08-09

## Description

The player terminal does not follow one coherent responsive scale across all font roles. Chrome, body, menu, title, and hacking text may resize at different rates instead of preserving a common proportional scale across viewport sizes.

Scrolling must not be available in the terminal presentation. In particular, when selecting a menu item opens an information-text view whose contents do not fit on one screen, the content must be divided into terminal-native pages, as on a real CRT terminal, instead of being exposed through a browser-page or localized content scrollbar. The same no-scroll expectation requires the existing exceptional-content and enlarged-view behavior to be reconsidered rather than relying on scroll containers.

## Artifact Traceability

### spec.md

- **Affected user stories**:
  - **User Story 1 — See the complete terminal at once**: its core value is seeing and operating the terminal without scrolling, but its acceptance scenarios only prohibit browser-page scrolling and do not prohibit localized scroll containers.
  - **User Story 2 — Use the terminal across desktop screen sizes**: Acceptance Scenario 1 requires text and spacing to scale, but does not require every font role to use the same responsive scale factor.
  - **User Story 3 — Reach exceptional and enlarged content**: Acceptance Scenarios 1 and 3 explicitly permit localized scrolling, which conflicts with the reported no-scroll requirement and provides no CRT-style pagination alternative.
- **Affected requirements**:
  - **FR-002** requires every presentation state to fit without browser-page scrolling, but does not prohibit scrolling within terminal regions.
  - **FR-003** requires the header, active content, and navigation controls to remain simultaneously visible; pagination must preserve these persistent regions.
  - **FR-004** requires text and controls to avoid overlap, clipping, and viewport escape; page splitting must satisfy this at every supported size.
  - **FR-006** requires text size and spacing to adapt, but does not define a common proportional scale for chrome, body, menu, title, and hacking text.
  - **FR-008** requires localized overflow for excess content, directly conflicting with the new requirement that scrolling not be available.
  - **FR-009** requires long authored values to remain accessible, but does not specify pagination as the no-scroll access mechanism.
  - **FR-010** expressly allows localized scrolling at 200% zoom, also conflicting with the reported requirement.
  - **FR-012** requires navigation behavior to remain intact; adding page navigation must not break menu, back, hacking, reveal, or audio behavior.
- **Affected success criteria**:
  - **SC-001** measures only browser-page scrollbars and therefore can pass while localized terminal scrollbars remain.
  - **SC-003** requires long content to remain reachable but does not require it to be paginated without scrolling.
  - **SC-004** allows any mechanism that keeps enlarged content reachable and does not assert no-scroll pagination.
- **Gap identified**: The specification simultaneously frames the complete no-scroll terminal as the primary experience and explicitly permits localized scrolling for overflow and zoom. It also lacks (1) a shared font-scaling rule and measurable proportionality criterion, and (2) pagination requirements for information views, including page capacity, page indicator/prompt, next/previous controls, keyboard operation, boundary behavior, and restoration of the current page during navigation.

### plan.md

- **Affected sections**: The implementation plan delegates all design to `spec.md § Approach`, especially the current CSS-focused responsive-sizing and overflow approach.
- **Impact**: The plan must be expanded beyond CSS containment. It must define a shared type-scale strategy and terminal-native pagination behavior for menu-selected information text, identify required rendering/state changes in `client/client.js` and any markup/control changes in `client/index.html`, and replace scrollbar-oriented verification with no-scroll and pagination checks.

### tasks.md

- **Affected tasks**:
  - **T001** — responsive shell dimensions, spacing, and type scaling.
  - **T002** — normal terminal header, menu, entry, output, prompt, and navigation visibility.
  - **T004** — exceptional-content overflow and long-value containment.
  - **T005** — document structure for responsive fitting, if pagination controls require markup changes.
  - **T006** — regression assertions for overflow prevention and persistent navigation.
  - **T007** — browser verification across the desktop viewport and zoom matrix.
- **False completions**: **T001, T002, T004, T006, and T007** are marked complete against criteria that do not enforce a common font scale, prohibit localized scrolling, or exercise paginated information views. **T005** must be reassessed and reopened only if the patched design requires document-structure changes.
- **Missing tasks**:
  1. Define and apply one proportional responsive scale to all terminal font roles while preserving their intended hierarchy.
  2. Replace scrolling in menu-selected information-text views with CRT-style page calculation, rendering, page indicators/prompts, and next/previous navigation.
  3. Define no-scroll behavior for other exceptional content and for 200% zoom so all information and actions remain accessible without browser-page or localized scrolling.
  4. Add regression coverage that rejects scrollable player regions, verifies proportional font scaling, and exercises multi-page text with mouse and keyboard input at every supported viewport.
  5. Repeat the production viewport/zoom matrix with representative one-page, exact-boundary, and multi-page information content.

## Root Cause Analysis

The feature artifacts interpreted “without scrolling” narrowly as “without browser-page scrolling” and intentionally selected localized overflow as the fallback for long or enlarged content. That decision produced requirements and completed tasks that can regard scrollable terminal regions as correct behavior. Separately, responsive typography was specified only as independently adaptive font sizes, not as a single proportional scaling system. CRT-style information pagination was never modeled as a requirement, interaction, success criterion, implementation step, or test case. The current behavior therefore reflects both a direct conflict with the clarified no-scroll requirement and missing specification detail for the replacement interaction.
