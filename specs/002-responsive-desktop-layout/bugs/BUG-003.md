# Bug Report: Password Game Does Not Fit the Screen

**Type**: Implementation drift
**Severity**: High
**Feature**: 002-responsive-desktop-layout (Responsive Desktop Player Layout)
**Reported**: 2026-08-10
**Status**: Patched
**Patched**: 2026-08-10

## Description

The player-facing password game does not fit completely within the available screen. The complete hacking interaction must remain visible in one terminal frame: header, attempts, both memory-dump columns, activity log, input preview, and every available interaction. The player must not need browser-page scrolling, localized scrolling, pagination, or clipped/off-screen content to operate the game.

The supplied [Fallout 4 reference screenshot](https://img.itch.zone/aW1nLzI0NTk0OTQ4LnBuZw==/original/TUjxTp.png) establishes the intended composition rather than an exact pixel target. It keeps the header and attempts above the board, places two dense memory-dump columns beside a narrow activity log, and leaves the input prompt visible at the bottom within one 630×500 image frame. The project layout should use the same screen-fitting principle across its supported viewport and zoom matrix while preserving this project's existing board data and controls.

## Root Cause Analysis

BUG-002 corrected the specification and planned a dedicated single-screen fit, but the reported player presentation still violates that contract. This is implementation drift accompanied by a verification escape: either the production layout does not apply the intended compact geometry in the affected viewport/font state, or the completed tests exercised a fixture or environment that did not reproduce the real rendered constraints. The supplied reference also makes clear that the board and log should be composed together within the available frame, so merely keeping some regions present in the DOM or reducing the entire game is not sufficient.
