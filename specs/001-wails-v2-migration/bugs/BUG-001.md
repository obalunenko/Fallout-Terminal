# Bug Report: Hidden Player States Appear While Scrolling the Live Menu

**Type**: Implementation drift
**Severity**: Medium
**Feature**: Wails v2 Runtime Migration (`001-wails-v2-migration`)
**Reported**: 2026-08-09
**Status**: Patched
**Patched**: 2026-08-09

**Feature-scope follow-up**: 2026-08-09 — The feature artifacts now use personal-use `.app` acceptance for migration cutover; optional Developer ID/public-release checks do not change this bug's verified player-state fix.

## Description

While a live terminal menu is displayed, a player can scroll the menu body and see the state-only messages `ОЖИДАНИЕ ТРАНСЛЯЦИИ_` and `Вход заблокирован.` / `Обратитесь к администратору.` even though the terminal is neither idle nor blocked.

The player presentation is expected to show exactly the state selected by the current live/navigation/hacking state. Idle content must be visible only when no terminal is live, and blocked content must be visible only after a hacking puzzle has failed.

### Reproduction

1. Start the application and connect a player browser.
2. Broadcast a terminal whose normal menu is tall enough for the terminal body to scroll.
3. Scroll through the live menu.
4. Observe the idle waiting message and blocked-access message within the same scrollable body as the active menu.

### Expected

Only the active live-menu state is rendered in the scrollable terminal body. Inactive idle and blocked states occupy no layout space and cannot be revealed by scrolling.

### Actual

The inactive `.term-idle` and `.hack-blocked` elements participate in layout despite their `hidden` attributes, so their messages become visible when the terminal body is scrolled.

## Root Cause Analysis

During player-client migration work associated with T040, `client/index.html` and `client/client.js` changed visibility control from explicit inline `style.display = 'none'` / `''` values to the HTML `hidden` attribute. The unchanged stylesheet still declares `display: flex` for `.term-idle`, `.hack-board`, and `.hack-blocked`.

Those author-level `display` declarations override the browser's default presentation rule for `[hidden]` in the affected rendering environment. As a result, JavaScript sets `element.hidden = true`, but the idle and blocked elements remain flex containers. Because both have `height: 100%` and are children of the scrollable `.term-body`, they consume layout space and can be revealed by scrolling.

The regression was not caught because the migration validation covered broad presentation and multi-client behavior but did not assert DOM visibility/layout exclusion for every inactive state under overflow.
