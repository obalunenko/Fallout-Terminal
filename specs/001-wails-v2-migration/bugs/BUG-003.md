# Bug Report: Dev Supervisor Interrupt Can Leave the Owned Tunnel Running

**Type**: Spec gap
**Severity**: High
**Feature**: Wails v2 Runtime Migration (`001-wails-v2-migration`)
**Reported**: 2026-08-09
**Status**: Patched
**Patched**: 2026-08-09

## Description

When public mode is active under the sole documented `wails dev` command, an
orderly native application Quit stops ngrok and removes the player listener and
temporary policy material. The acceptance evidence also records that interrupting
the Wails development supervisor can bypass the native shutdown callback and
leave the owned ngrok process alive, requiring a targeted manual `kill`.

The development entry point is part of the migration's one-command lifecycle.
A handled supervisor interrupt must not leave public access running after the
owning development command has stopped.

## Root Cause Analysis

The Go application owns ngrok correctly while its Wails lifecycle callbacks run.
The development supervisor is a separate orchestration layer and may terminate
the native process without allowing `OnShutdown` to finish. The original spec
treated normal native Quit as the decisive shutdown boundary and documented the
supervisor case as recovery guidance, so no acceptance gate required automatic
cleanup for this handled development interruption.

## Recommended Fix

1. Run `/speckit.bugfix.patch BUG-003` to add the missing development-interrupt requirement and lifecycle tasks.
2. Add a regression harness that starts public development mode, triggers the documented handled interrupt, and asserts zero owned ngrok processes, listeners, and policy directories after the timeout.
3. Implement an ownership strategy that does not depend solely on the native window shutdown callback.
4. Run `/speckit.bugfix.verify BUG-003`, then resume `/speckit.implement` and repeat final acceptance.
