# Bug Report: Accepted Wails Artifact Hash Is Inconsistent Across Evidence

**Type**: Implementation drift
**Severity**: Medium
**Feature**: Wails v2 Runtime Migration (`001-wails-v2-migration`)
**Reported**: 2026-08-09
**Status**: Patched
**Patched**: 2026-08-09

## Description

The rollback guide identifies the pre-cutover Wails executable hash
`ec013929e5962c79edbdd633bb3986cbe271ac9f5d35fa43c5e6efe63b90509a` as the
accepted personal-use artifact. The final post-Electron acceptance evidence in
`quickstart.md` records a later rebuilt executable with hash
`84a99810993a952706c43a099f26be4d18c33390a0d1023096b6b09bc6eb2e29`.

The repository therefore does not identify one unambiguous final artifact for
cutover and rollback decisions. An operator following the rollback guide can
verify the wrong build even though the final acceptance evidence describes a
different executable.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 4 — Install, validate, and roll back the personal-use application.
- **Affected requirements**: FR-020, FR-023, FR-024, SC-007, and SC-008.
- **Gap identified**: The specification requires recorded package and rollback evidence but does not explicitly require every cutover document to name the same final accepted artifact and digest.

### plan.md

- **Affected sections**: Phase 5 — Cutover; Verification Plan — Packaging and Legacy regression.
- **Impact**: The post-removal rebuild must become the canonical acceptance artifact, and its identity must be synchronized into rollback guidance after the last acceptance build.

### tasks.md

- **Affected tasks**: T060, T069, T070, and T074.
- **False completions**: T074 is marked complete although the rollback guide still points to the earlier T060 executable rather than the final T069 post-Electron executable.
- **Missing tasks**: Add a final evidence-consistency check that compares the canonical candidate identity and SHA-256 across `quickstart.md`, rollback guidance, and release notes before handoff.

## Root Cause Analysis

T060 recorded a valid personal-use candidate before the Electron source was
removed. T069 then rebuilt and reaccepted the application after legacy removal,
which necessarily produced a different executable digest. The final digest was
added to `quickstart.md`, but T074's rollback record was not refreshed after the
later build. The task ordering allowed documentation completion before the
canonical post-cutover artifact existed.

## Recommended Fix

1. Run `/speckit.bugfix.patch BUG-002` to require one canonical post-cutover artifact and reopen the stale rollback-document task.
2. Rebuild or select the official final candidate, record its identity once, and synchronize its SHA-256 across all acceptance and rollback evidence.
3. Run `/speckit.bugfix.verify BUG-002` to confirm cross-artifact consistency.
4. Resume `/speckit.implement` to complete the reopened documentation and evidence task.
