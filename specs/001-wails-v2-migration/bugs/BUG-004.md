# Bug Report: Transitional Electron Bridge Name Remains After Final Cutover

**Type**: Spec conflict
**Severity**: Low
**Feature**: Wails v2 Runtime Migration (`001-wails-v2-migration`)
**Reported**: 2026-08-09
**Status**: Patched
**Patched**: 2026-08-09

## Description

The Wails frontend correctly routes privileged commands through generated Go
bindings and Wails events, but the final renderer facade is still published as
`window.electronAPI`. `master.js` consumes the same Electron-specific global
even though Electron, preload IPC, and the Node runtime have been removed.

The compatibility name was useful during staged migration. Keeping it after the
final cutover leaves an obsolete runtime concept in active source and makes the
new bridge appear to depend on Electron.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 1 — Run the game-master workspace without behavior loss.
- **Affected requirements**: FR-004, FR-025, and FR-026.
- **Conflict identified**: The impacted-surfaces section permits preserving renderer-facing method names during migration, while FR-025 says removal of the old runtime and its bridge is the final migration action. The spec does not distinguish a temporary compatibility alias from the final runtime-neutral bridge contract.

### plan.md

- **Affected sections**: Desktop bridge; Phase 0 — Research and decisions; Phase 3 — Game-master and player integration; Phase 5 — Cutover.
- **Impact**: Preserve the facade's method behavior but publish it under a runtime-neutral name after cutover, then verify active production source contains no Electron-specific bridge identifier.

### tasks.md

- **Affected tasks**: T029, T052, T064, T065, and T070.
- **False completions**: No original implementation task was false when completed; T029 intentionally introduced the compatibility alias for staged migration. Final cleanup lacked a follow-up removal task.
- **Missing tasks**: Add a regression/static-contract test for a runtime-neutral facade, rename the global and consumers without changing method/event behavior, and verify Electron references remain only in historical migration and rollback documentation.

## Root Cause Analysis

The migration used a strangler approach that minimized changes to `master.js` by
preserving the preload-era global shape. The plan correctly introduced that
adapter but did not define when its transitional Electron-specific name must be
retired. Legacy runtime files were removed before a final terminology cleanup
was represented in the task graph.

## Recommended Fix

1. Run `/speckit.bugfix.patch BUG-004` to resolve the transitional-versus-final bridge naming conflict.
2. Introduce a runtime-neutral `window.desktopAPI` facade, migrate all active consumers, and preserve the existing narrow method/event behavior.
3. Add a source-level regression check that rejects active Electron bridge references outside historical documentation.
4. Run `/speckit.bugfix.verify BUG-004`, then resume `/speckit.implement`.
