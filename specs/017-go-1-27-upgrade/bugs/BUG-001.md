# Bug Report: Raw Go Tests Emit macOS Deployment Warnings

**Type**: Implementation drift

**Severity**: Low

**Feature**: `017-go-1-27-upgrade`

**Reported**: 2026-08-21

**Status**: Patched

**Patched**: 2026-08-21

**Verified**: 2026-08-21 — A fresh-cache `make test` passed with zero `ld: warning` lines.

## Description

Running `go test ./internal/platform` directly on macOS 26.5 with Go 1.27.0 and a fresh build cache succeeds but emits linker warnings because the raw Go invocation links for the arm64 default macOS 11 target while project and SDK objects target macOS 13 or 26. The repository's canonical `make test` and `make check` paths already export `MACOSX_DEPLOYMENT_TARGET=13.0` with matching CGO compile and link flags and do not emit the warnings.

### tasks.md

- **False completions**: None. T008 used `make check`, which already supplies the correct environment and passed.
- **Missing tasks**: Add a regression task that runs the canonical test path with a fresh Go cache and asserts that no linker warning is emitted.

## Root Cause Analysis

The diagnostic follow-up invoked `go test` directly, bypassing the environment exported by the repository's Makefile and CI. Go's raw darwin/arm64 default links for macOS 11, while this project supports macOS 13+ and the installed macOS 26.5 SDK produces newer object metadata. Supplying the existing project environment eliminates every warning without source, dependency, or generated-code changes.

## Recommended Fix

1. Patch the specification to require warning-free macOS validation under the governed deployment environment.
2. Patch the plan to make `make test` or an explicitly equivalent environment the canonical local validation path.
3. Add T010 to verify a fresh-cache canonical test run emits no `ld: warning` output.
4. Verify cross-artifact consistency, run T010, and close the bug.
