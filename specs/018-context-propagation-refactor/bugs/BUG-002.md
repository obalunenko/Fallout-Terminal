# Bug Report: Player Page Emits Avoidable Console Diagnostics

**Type**: Spec gap

**Severity**: Low

**Feature**: `018-context-propagation-refactor`

**Reported**: 2026-08-21

**Status**: Patched

**Patched**: 2026-08-21

## Description

Opening browser developer tools on the local player page at `127.0.0.1:3690` shows four console
entries in the supplied log:

1. Chromium warns that the Content Security Policy directive `frame-ancestors` is ignored when it
   is delivered through an HTML `<meta>` element.
2. `36.js` prints `GeneratedSessionID Object`.
3. `frame.js` reports that `unload` is disallowed by the document's permissions policy.
4. The browser's automatic request for `/favicon.ico` receives `404 Not Found`.

The first and fourth entries are attributable to the player application. The source HTML includes
`frame-ancestors 'none'` in its CSP meta element even though browsers only enforce that directive
from an HTTP response header, and the player asset set provides neither a favicon declaration nor a
`favicon.ico` resource. The server already sends the complete CSP, including `frame-ancestors`, as
an HTTP response header, so the ineffective meta directive is redundant rather than a loss of the
intended anti-framing protection.

The second and third entries are not attributable to repository-owned code from the supplied
evidence. Neither `36.js` nor `frame.js` exists in the player asset tree, neither is referenced by
the application, and `GeneratedSessionID` does not occur in repository source. They are most likely
browser- or extension-injected scripts and should be reproduced in a clean browser profile before
any application change is proposed for them.

The log contains no uncaught JavaScript exception, failed ConnectRPC request, or player-stream
failure. The observed first-party impact is avoidable developer-console noise and a needless HTTP
404, not a demonstrated player-visible malfunction.

### Reproduction

1. Start the application so the player server listens on `127.0.0.1:3690`.
2. Open the player page in Chromium.
3. Open Developer Tools and inspect the Console and Network panels.
4. Observe the ignored `frame-ancestors` meta directive and the failed `/favicon.ico` request.
5. Repeat in a clean profile with extensions disabled to determine whether the `36.js` and
   `frame.js` entries disappear.

**Expected**: The first-party player page loads without first-party console warnings/errors or
failed requests, while anti-framing protection remains enforced by the HTTP CSP header.

**Actual**: The page emits an ignored-directive warning and returns 404 for the browser's favicon
request. Two additional diagnostics originate from scripts that are absent from the shipped player
assets and cannot yet be assigned to the application.

## Root Cause Analysis

This is primarily a specification and coverage gap rather than drift from an existing requirement.
The player CSP was added to `frontend/client/index.html` with `frame-ancestors 'none'`, and the same
directive is correctly supplied by `internal/player/http.go` in the HTTP response header. The
browser warns about the meta copy because `frame-ancestors` is not supported through CSP meta
delivery. A static source test in `internal/platform/assets_test.go` currently requires the invalid
meta fragment, so the existing suite preserves the warning instead of detecting it.

Separately, the browser performs its conventional `/favicon.ico` lookup, but the player asset tree
contains no matching resource and the static handler correctly returns 404 for unknown paths. No
test defines a favicon contract or checks the initial page's complete request set.

The current feature's browser regression was added to prove that the context-propagation change no
longer cancels live player connections after startup. That regression validates subscription and UI
behavior, not developer-console cleanliness. The Go, race, and leak gates likewise cannot observe
browser-generated CSP warnings or an incidental favicon request. This allowed both first-party
diagnostics to coexist with completed T020/T021 and passing functional behavior.

The remaining `36.js` and `frame.js` entries should not be folded into the application fix without
new evidence. Their filenames and logged symbol are absent from the repository-owned player assets,
which strongly indicates injected browser tooling rather than a shipped player dependency.
