# Bug Report: Completed Startup Cancels Player Connections

**Type**: Implementation drift

**Severity**: Critical

**Feature**: `018-context-propagation-refactor`

**Reported**: 2026-08-21

**Status**: Patched

**Patched**: 2026-08-21

## Description

After the Overseer publishes public access and puts a terminal on air, players can open the public
page and see the character-selection screen, but they cannot remain connected. The player UI is
covered by `СВЯЗЬ ПОТЕРЯНА — ПЕРЕПОДКЛЮЧЕНИЕ...` and repeatedly reconnects instead of
maintaining the generated ConnectRPC `Subscribe` stream.

The screenshot reported with this bug shows the complete player shell and character choices in the
background while the lost-connection overlay remains active. This is a regression of the accepted
public-player behavior previously corrected under `007-embedded-ngrok-access/BUG-003`.

### Reproduction

1. Launch the production application with the default non-zero player startup timeout.
2. Configure and publish the Overseer's public connection.
3. Put a terminal on air.
4. Open the published URL as a player and complete the public authentication challenge.
5. Observe the character-selection UI behind the persistent lost-connection/reconnect overlay.

**Expected**: the committed player listener remains owned by the application runtime, a player
receives the current complete snapshot, and `Subscribe` remains open for later authoritative
updates until player disconnect, server stop, or application shutdown.

**Actual**: successful application startup cancels the context inherited by the committed HTTP
server and its ConnectRPC requests. The listener can still deliver the page (and may deliver an
initial snapshot), but the subscription observes cancellation and closes.

## Root Cause Analysis

The regression was introduced by the context-propagation refactor in commit `7c70a8b`.

Production composition configures a 20-second startup timeout in `main.go`. `App.Start` creates a
bounded `acquisitionContext`, passes it to `Player.Start`, and defers cancellation with
`errApplicationStartupComplete` when startup returns (`app.go:1011-1023`). `Server.Start` creates
its long-lived `serverContext`, but also registers `context.AfterFunc` on that acquisition context
to cancel the server context (`internal/player/server.go:101-108`). The same server context is then
installed as `http.Server.BaseContext` (`internal/player/server.go:113-119`).

Consequently, the normal successful return from `App.Start` triggers the deferred startup cancel,
the `AfterFunc` cancels `serverContext`, and every later HTTP/Connect request begins with an already
canceled context. Static response handling can still render the bundled player page, and a stream
may expose its first state before cancellation wins, which explains the visible character choices;
the long-lived subscription then terminates and the frontend enters its reconnect overlay.

This affects the sole player listener rather than only ngrok. The public URL makes the failure
visible, but the source-level lifetime error is transport-independent whenever the configured
startup timeout is non-zero.

Existing tests did not catch the regression because the player-server test keeps its `Start`
context alive until the test ends, application lifecycle tests use a recording player fake rather
than the real HTTP server, and public-stream tests assemble their server and ingress independently
of the production `App.Start` timeout lifecycle.

## Recommended Fix

1. Run `$speckit-bugfix-patch BUG-001` to encode the explicit player-server ownership handoff and
   dependency-ordered RED/GREEN tasks in the feature artifacts.
2. Keep the startup context capable of aborting acquisition before commit, but detach it after a
   successful listener handoff. Root the committed HTTP server in the application/player-server
   owned context and cancel it only for the documented runtime causes.
3. Run `$speckit-bugfix-verify BUG-001` to confirm spec, plan, contract, and task consistency.
4. Resume `$speckit-implement` and require the focused handoff regression, reported public-player
   journey, complete suite, and race suite to pass before closing the bug.
