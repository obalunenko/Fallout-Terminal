# Bug Report: Dud Removal Rebuilds the Entire Hacking Board

**Type**: Spec gap
**Severity**: Medium
**Feature**: CRT Rendering and Motion Effects (`008-crt-rendering`)
**Reported**: 2026-08-17
**Status**: Patched
**Patched**: 2026-08-17

## Description

When a player activates a hacking delimiter pattern and its authoritative outcome removes a dud word, the player client tears down and rerenders the entire password board. The replacement board then starts another progressive code-row reveal even though the hacking puzzle generation has not changed.

Expected behavior: a dud-removal update within the current hacking generation must preserve the existing board DOM and reveal progress. Only the affected dud content and related pattern/log presentation should update; already revealed rows must keep their node identity and must not disappear or replay. If the affected row has not yet been revealed, its updated authoritative content should appear when that row reaches its existing reveal position without making the row interactive early. A genuinely new puzzle generation may still replace and reveal the whole board.

Actual behavior: the authoritative dud-removal path replaces the selected candidate text with dots and removes its word entry. `hackRevealIdentity()` includes the complete rendered column text and word map, so this legitimate same-generation mutation changes the reveal key. `renderHackScreen()` consequently calls `renderHackColumns()` as a new reveal, and the reveal controller clears and reconstructs the complete hacking board.

## Root Cause Analysis

BUG-001 correctly prevented attempts, log, hover, reconnect, and layout work from replaying an unchanged hacking board, but it made the full rendered board part of reveal identity so changed board text could identify a replacement puzzle. Hacking gameplay also mutates board text within a stable generation: dud removal dots one candidate and removes its word metadata. Because the presentation model has no separate in-generation mutation state, the client follows the specified replacement path and rebuilds the entire board.

This is a requirements and state-model omission rather than a dependency problem. The current implementation is consistent with FR-018, FR-019, Research Decision 5, and the Reveal Sequence model; those artifacts need a narrower replacement boundary before the client can preserve the board during dud removal.
