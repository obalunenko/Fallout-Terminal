# Bug Report: Hacking Code Rows Zoom Out During Progressive Reveal

**Type**: Spec gap
**Severity**: Medium
**Feature**: CRT Rendering and Motion Effects (`008-crt-rendering`)
**Reported**: 2026-08-19
**Status**: Patched
**Patched**: 2026-08-19

## Description

When a player enters the hack game and the code rows are progressively rendered, the visible code text starts at a larger size and repeatedly becomes smaller as more rows appear. The resulting zoom-out effect is not part of the intended reveal animation.

Expected behavior: the complete hacking board must be fitted before the first code row becomes visible. One font size, calculated against the full board and the current viewport, orientation, activity-log allocation, and active font metrics, must remain visually stable while rows reveal. Appending another reveal row must not by itself change the computed text size. A genuine viewport, orientation, or font-metric change may request a new full-board fit, but the fit must still use the complete puzzle rather than only the currently revealed subset.

Actual behavior: `renderHackColumns()` passes `afterAppend: scheduleHackFit` to the reveal controller. Every 40-millisecond row append therefore schedules `fitHackLayout()`. `fitHackRowFont()` measures only `.hack-row` nodes already attached to `hackColumns`, so the early partial board allows an oversized result; as more rows are appended, the height constraint becomes progressively tighter and the fitted font shrinks. The player sees this repeated refitting as a zoom-out animation.

## Root Cause Analysis

The responsive-layout feature introduced a maximal hacking-row font fit for a complete 16-row board. The later CRT hacking reveal retained that fitter but invoked it after each row append. Because unrevealed rows are intentionally absent from the interaction DOM, the fitter sees an incomplete height constraint during early reveal frames and selects a font size that cannot fit the eventual complete board. Each subsequent append reduces the available height per row and produces a smaller result.

The existing CRT artifacts protect reveal identity, timer progress, node ordering, and interaction gating, while the responsive artifacts protect the final complete-board geometry. No artifact joins those contracts by requiring the final full-board fit to be established before progressive painting and held stable during ordinary reveal callbacks. The missing cross-feature invariant allowed the implementation and tests to treat every append as fitting-relevant content growth.
