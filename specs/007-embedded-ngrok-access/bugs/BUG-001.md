# Bug Report: Dedicated `127.0.0.2` Ingress Cannot Bind on Target macOS

**Type**: Dependency issue / spec conflict
**Severity**: Blocking
**Feature**: `007-embedded-ngrok-access`
**Reported**: 2026-08-15
**Status**: Patched
**Patched**: 2026-08-15

## Description

The approved public-ingress design requires the embedded ngrok upstream dialer to bind its local
TCP source to `127.0.0.2` before connecting to `127.0.0.1:3690`. On the target Darwin host, `lo0`
has only `127.0.0.1`; the mandatory real-loopback test fails with `EADDRNOTAVAIL`:

```text
dial tcp4 127.0.0.2:0->127.0.0.1:3690: bind: can't assign requested address
```

Adding a loopback alias would require machine-level privileged configuration and would make the
packaged personal-use application fail its no-Terminal/no-environment acceptance. Falling back to
the default dialer while retaining player-side Host classification would also invalidate the
claimed source boundary.

The game-master requirement is intentionally lightweight: provide a recognizable public ngrok
HTTPS link for a private game with friends and use a password to prevent accidental entry, not to
provide a hardened hostile-network security boundary.

## Patched Decision

1. The embedded SDK forwards directly to the existing `http://127.0.0.1:3690` player service using
   the SDK's ordinary upstream connection path; there is no custom source-bound dialer.
2. The ngrok endpoint is created with one Basic Auth Traffic Policy before its URL is published.
   Direct local/LAN traffic does not traverse that endpoint and remains unauthenticated.
3. Player-side public Host/source admission is removed. The existing player service, port 3690,
   ConnectRPC handlers, server-authoritative state, and streaming implementation remain singular.
4. The token and password remain Keychain-only at rest. They may cross only transient private UI
   inputs, the explicit SDK Agent/Traffic Policy construction call, and the standard browser Basic
   Authorization exchange; no reusable readback/log/event/status/persistence surface is added.
5. Deterministic tests prove exact policy construction, lifecycle, redaction, and local isolation.
   A focused credential-gated real test checks missing/wrong/correct auth plus a non-empty
   `Subscribe`; unavailable prerequisites remain honest `NOT RUN` and do not block deterministic
   completion.

## Superseded Alternatives

- Privileged `lo0` alias creation, a default-dialer fallback hidden behind the old player policy,
  Host-only public inference, and a second player server remain rejected.
- A private loopback reverse proxy remains a future fallback only if the focused real ngrok Traffic
  Policy test demonstrates an actual streaming incompatibility.
